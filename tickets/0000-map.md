# Personal AI Glossary — Wayfinder Map

Tracker convention (local-markdown): each ticket is a file in `tickets/`, child of
this map. Frontmatter carries `status` (open/closed), `labels`
(`wayfinder:research|prototype|grilling|task`), `assignee` (claim = assigned),
and `blocked-by` (list of ticket filenames). A ticket is on the **frontier**
when it is open, unassigned, and everything in `blocked-by` is closed.

## Destination

A working v1, built in this repo: a personal, cross-project
ubiquitous-language glossary (terms + one-line meanings, no style rules, no
concept modeling) whose data lives user-globally. Not necessarily a Claude
Code plugin — the packaging/distribution mechanism (e.g. npx-installed
skills) is its own open decision; Claude Code is simply the first consumer.
Reached when the tool is installed, seeded with real terms, a Claude Code session
demonstrably uses the user's terminology unprompted, and an agent can propose
new terms for human approval. Notes override: this map carries execution
tickets — it ends with the thing working, not a spec.

## Notes

- Domain: Claude Code extension mechanics (plugins, skills, CLAUDE.md-style
  context loading, MCP), personal knowledge management.
- Skills to consult: `/grilling` + `/domain-modeling` for decision tickets,
  `/prototype` for prototype tickets, `/research` for research tickets,
  `/writing-for-agents` when authoring the tool's own docs/skills.
- Standing preferences: Claude Code first, other harnesses later. The glossary
  is a module **decoupled from** the user's llm-wiki — the wiki may later
  consume it, never the reverse. Capture is propose-then-human-approve, never
  silent self-editing. Terminology only: communication style stays in
  CLAUDE.md; project-specific terms stay in per-repo CONTEXT.md.

## Decisions so far

<!-- one line per closed ticket: gist + link -->

- Charting session (this map): language = terminology only (a term + one-line
  meaning); store is standalone, Claude Code-first, bidirectional
  (read + propose); code lives in this repo, data lives user-globally;
  loading strategy to be settled via research **and** prototype, not gut.
- [Skill distribution mechanisms](0002-research-distribution.md) — four viable
  channels can coexist from one repo; recommended: clean SKILL.md repo +
  optional `.claude-plugin/` layer + harness-neutral data dir; npm postinstall
  is dead, skip it. Full findings on branch `research/skill-distribution`.
- [Prior art — existing personal-glossary tools](0009-research-prior-art.md)
  — nothing does all four requirements; **imitate**: citypaul's
  propose-then-approve capture protocol + terrylica's user-global location;
  personal glossary owns the operator's *meta*-language, defers to per-repo
  glossaries by an explicit precedence rule. Findings on branch
  `research/prior-art`.

## Not yet specified

- **Build of v1** — the actual code structure and how its pieces (loading,
  capture, approval) assemble. Sharpens once the loading-strategy, term-shape,
  capture-flow, and packaging tickets close.
- **Proof of use** — how we validate "a session demonstrably speaks the
  user's language"; depends on which loading strategy wins.
- **In-session proposal UX** — how a running agent surfaces "you say X, I say
  Y — add to glossary?" without derailing work; hangs on the capture-flow
  decision.

## Out of scope

- **Wiki integration** — llm-wiki consuming the glossary. Deliberately
  deferred; the glossary is designed decoupled so this stays possible.
- **Other harnesses** (Cursor, ChatGPT, etc.) — Claude Code first; expansion
  is a fresh effort.
- **Communication-style preferences** — already covered by the user's global
  CLAUDE.md; this glossary is terminology only.
